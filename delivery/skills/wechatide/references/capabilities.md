The operations of initializer, compiler, debugger, previewer, project-manager, automator and cloudbase-operator are the only registered CLI operations, called through the [CLI contract](cli.md) on macOS.

Directory presence, a tool name in historical material, or a legacy installed skill does not add a callable capability to this delivery.

## Request and result continuity

Reuse the existing task record; no new persistent schema is required. Retain the goal, nextScene, confirmed absolute project path, requested change, authorization scope and limits, and current blocker. Preserve confirmed login, version, window, AppID, environment, page and selector facts when supplied, including their evidence and limits. They do not make an unavailable operation callable. Ask only for facts or decisions that cannot be resolved from authorized context. Do not guess a project, AppID, environment or permission. Carry effective Human authorization through router and child handoffs without requiring approval at each layer. Target and effect checks still apply to each operation; a new child entry does not expand the grant or bypass a host refusal.

For a returned configuration result, check the exact project, changed files and fields, before/after effective values, validation and unresolved blockers. Distinguish read-only inspection, no change needed, completed local editing, partial editing and failure. File validation does not prove DevTools has reloaded the configuration or that compilation, preview, upload or cloud operations succeeded. For a returned initializer or compiler result, check the exact operations, project and facts against their JSON results. A shown QR code, an opened window or a triggered refresh does not prove login, compilation or runtime correctness. For a returned debugger result, check which pattern produced each line and whether a mock or cleared cache remains in place. Filtered evidence is not the whole buffer, and a screenshot is not a passing test. For a returned previewer result, check whether the code left this machine. A pushed preview or QR code reaches the developer's own WeChat, an upload publishes the trial version, and a pending confirmation is neither. For a returned project-manager result, check whether code left or entered this machine and whether the list actually changed: a snippet link means the project was uploaded, and an import downloaded code without opening or checking it. Report subsequent inspection and execution from their actual evidence; a removal changed only the list. For a returned automator result, check that each assertion cites a read or a screenshot rather than a dispatched interaction, and what remains changed: page data, a mock, the signed-in test account or real-device debugging. For a returned cloudbase-operator result, check the exact AppID and environment it names and what changed outside this machine: a deployed function, a created or dropped collection, changed documents, an uploaded or deleted file, or a replaced subscription. A partial result is not a completed write, and a returned temporary link expires. For a returned installer result, check which refusal it explains and that it changed nothing. A compatible verdict is not a working call, and a threshold read from the repository rather than the installation may be behind upstream. Downloading, installing, updating and PATH repair stay with the Human.

If existing context contains a pendingTask, preserve it as [pending tasks](tasks.md) define, including its polling round. Do not reissue the original operation or mark the task complete during handoff. Only initializer's login and authorization tasks are actively polled. Every other task stays retained with its dependent work blocked, including a previewer, project-manager, automator or cloudbase-operator confirmation. Never copy access tokens into a handoff, repository, ordinary log or memory.

## Operations outside this delivery

Every scene of the upstream skill now has a delivered entry. The executor refuses any operation that is not a registered ID, including the MCP bridge, the CLI's own aliases and the deprecated project_setting operations.

Installer diagnoses an installation but delivers none of upstream's installation actions: downloading a package, running an installer, updating DevTools and repairing PATH or links remain the Human's, and no entry performs them. Upstream's channel selection, package resolution and PATH-repair modules are recorded as inputs in the source record and are not adopted.

A future CLI consumer uses the delivered [CLI contract](cli.md) and [pending tasks](tasks.md), extends the call executor's operation list with its own operations, and carries forward the retained parameter and project-error contracts with their actual owners. It must not activate the legacy registry wholesale. The historical project_setting_get and project_setting_update operations remain retired; local configuration belongs to project-config.
