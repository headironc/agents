# 工具契约归属与绑定

本页按需提供本仓库检查器的调用约束。它也收录 Git、SSH、curl、jq 和 rg 的约束。只读取当前工具所需的小节。工具合同本身不授予操作权限。

## 执行上下文

代码工具的通用性不免除目标绑定。Git、构建、测试，以及执行代码任务的 Codex，都必须绑定实际执行位置。核对宿主、目录和仓库，按操作核实分支或 detached 状态、基线、候选及相关未提交内容。同一 Project 可以含多个仓库，同一仓库可以含多个 worktree。名称、共同 Git 历史或相同 HEAD 不能替代实际候选。

通过工具支持的工作目录或目标参数执行，核实际生效位置及输入。分别核会话 cwd 和工具执行目标。使用受管附件或客户端 Project 分组时，再核相应绑定。无分组入口的客户端直接核目录。前一项正确不能证明后一项正确。创建或切换尚未完成时，不执行依赖新绑定的写入或验收。仅改变设置、阅读另一候选或收到成功回执，不证明运行中的工具已经切换。

首次绑定及宿主、目录、仓库或候选输入变化时，核实受影响事实。同一绑定未变时复用有效证据，不逐命令重复全量检查。结果保留实际输入与覆盖范围，检查复用遵循[验证规则](review.md#checks)。在途和未知操作保留原目标与句柄，不因换目录而重启。不涉及仓库的任务只绑定适用的执行位置和材料，不虚构 Git 状态。

## task-temp

Contract subject: `task-temp`.

使用固定 Node 运行交付的 `tools/task-temp.mjs`。`run --owner TASK --purpose TEXT [--root DIR] -- COMMAND [ARG...]` 为一次前台命令分配私有目录。owner 使用可回查的任务或会话标识，purpose 说明用途，不含凭据。root 默认为系统临时目录，也可指定已存在的物理目录。工具保持命令原工作目录，将 `TASK_TEMP_DIR`、`TMPDIR`、`TMP` 和 `TEMP` 指向分配目录中的 `scratch`。命令须实际使用这些变量；硬编码到其他路径的产物不在管理范围。

只运行等待全部子进程结束的前台命令。不要用于后台服务、脱离的进程、未知外部写或 Git worktree。命令正常退出时，包括非零退出，工具检查归属后移除本次新建目录。运行前把验收原件、恢复材料及需保留的诊断输出选到目录之外。stdout 和 stderr 继承调用端；工具不保留内部临时日志。既有目录与共享缓存不参与清理。该入口不扩大被执行命令的业务权限。

工具向 stderr 输出分配位置和最终 `removed` 或 `retained` 结果。收到中断时转发信号并等待直接子进程，不强杀后自动删除。子进程被信号终止、启动失败或归属变更时保留目录。发现 `.git`、特殊文件、检查或删除失败时也保留，并报告原因。强杀或宿主退出可能只有最初的归属标记。后续由所有者核实进程、原操作及剩余材料。删除失败可能已部分移除临时文件，保留结果不保证完整恢复副本。

`scan [--root DIR]` 只读枚举指定目录的直接子目录，默认扫描系统临时目录。无参数等同 `scan`。可分别指定临时根和客户端 worktree 根。扫描不读取会话数据库，不操作 Git，也不递归估算容量。扫描不认定任务结束。有效标记显示归属；没有标记显示 `unmanaged`。链接只列出、不跟随；无效或不可读标记单列错误。`needs-owner-check` 表示待核归属及占用，不表示可删除。扫描不创建目录，不修改标记，不提供删除选项。读操作可能更新文件系统 atime。

`--version` 输出裸版本号，`--help` 输出用法。扫描成功退出 0，任一读取错误退出 1。顶层读取失败写 stderr 并退出 1。run 正常清理后保留命令退出码；保留目录时至少退出 1。参数错误退出 1。扫描缺少子目录、任务 idle、目录年龄或 PID 消失均不能证明可清理。后续回收沿原授权与工作区收尾规则执行。

## rg

Contract subject: `rg`.

使用 `rg` 或 `rg --files` 检索。字面名称使用字面匹配；范围包含相关隐藏或忽略文件时显式纳入。区分无匹配和检索失败，报告覆盖范围中的排除项。

## jq

Contract subject: `jq`.

使用固定过滤器，通过 `--arg` 或 `--argjson` 传值。保留生产命令与解析各自的失败。按实际谓词解释 `-e`。解析成功不代表响应结构或业务结果正确。

## curl

Contract subject: `curl`.

使用实际可执行文件，为 URL 和输入加引号，通过 `--data-urlencode` 编码查询值。保留端点、请求头、超时、重试额度。目标文件和验证要求也必须保留。分别检查传输、HTTP 状态和应用结果。诊断中不暴露凭据或敏感响应。

## Git

Contract subject: `git`.

在已核实的工作树执行命令。网络操作前核对 remote、refs 与有效 URL：`git remote get-url --all`。推送前还必须运行 `git remote get-url --push --all`，涵盖 URL 重写、全部推送目标及适用的 SSH alias。保留已确认的传输和凭据配置。新增 GitHub remote 默认使用 HTTPS，通过 gh 凭据助手认证。其他 Git 服务沿用其已确认的协议；新增来源未指定协议且无既有约定时，优先 SSH。协议默认值不授权改写已有 remote 或安装凭据助手。

按实际传输核对身份与访问。HTTPS 操作核对有效凭据助手及其选用账号，并验证目标仓库访问。gh 的 API 身份不单独证明 Git 使用相同凭据，也不证明目标仓库的推送权限。SSH 操作按下节核对身份。提交署名和签名密钥独立于传输认证；切换 gh 账号不授权更改仓库的提交身份或签名配置。

使用 fetch 刷新远程状态，成功后再绑定基线。不要用 pull 隐式合并或 rebase。发布前核对授权目标、分支、最终内容和保护要求。直接推送时指定 remote。refspec 包含完整 source:destination。随后核对远程 ref 和对象 ID。结果未知时先回读，遵守调用操作的重试额度。历史重写必须取得明确授权。

## SSH

Contract subject: `openssh`.

复用已配置的主机别名和凭据，保留 host-key 验证。访问失败不授权更换身份、remote、凭据或信任记录。GitHub API 身份不能证明 SSH 身份。操作要求特定 SSH 身份时，必须取得该传输的证据。

## gitleaks

本节是 `gitleaks` 的调用说明。主体定义在仓库的 `scripts/check.ts` 头部，不在本页。

运行 `gitleaks dir <路径> --no-banner --redact --ignore-gitleaks-allow --config <配置>` 扫描工作树。`--redact` 让命中值不进入日志与报告。忽略源码与讨论中的 `gitleaks:allow` 行内豁免；允许项写在配置里，逐条收窄到具体值。

**不要用 `paths` 给某个文件整体开口子。** 它按整文件豁免，同文件里后来加进去的真实凭据不再上报。本仓库实测过这一点。已豁免文件植入真实形态的 token 后，未被报出。只按值允许。

`target/` 等构建目录可由 `.gitignore` 排除提交候选，安装候选也应排除它们。仓库门禁通过 `scripts/check-secrets.ts` 扫描 Git 已跟踪及未忽略的未跟踪文件。源码枚举固定到传入仓库，不继承调用者的 `GIT_*` 环境与全局 Git 配置。Git 文件名无法按 UTF-8 解码时，门禁失败，不静默跳过该文件。报告路径的忽略检查使用相同 Git 环境。被强制跟踪的构建文件仍在范围内，普通忽略产物不在范围内。不要为缩短扫描给构建目录增加 `paths` 豁免。

本仓库门禁用它扫描 Git 源码候选的临时副本。扫描前逐条核对副本与复制前的源码文件条目。还要复查工作树；任一不一致都使门禁失败。

退出码 0 表示无命中，1 表示有命中。无命中不证明没有密钥。扫描依赖模式，自造形态可能不在规则里。

## prose-check

本节是 `prose-check` 的调用说明。主体定义在仓库的 `scripts/check-prose.mjs` 头部，不在本页。

先将 `AGENTS_DELIVERY_ROOT` 设为当前这份合同的物理目录的上级，即本产品的部署根。运行 `node "${AGENTS_DELIVERY_ROOT}/tools/check-prose.mjs" PATH...`。目录会递归，只读 `.md`。保留的历史材料用 `--exclude 前缀` 排除，`--format json` 输出结构化结果。

`--version` 只打印一个裸版本号。消费者的工具清单按此版本号固定本工具。方式与其他固定工具相同。

`--errors-only` 只列阻塞的空格错误。句长发现都是编辑建议，逐条列出会把真正失败的那些淹掉。汇总行照常报建议条数，`--format json` 下这个数写成 `cautionsNotListed`。整棵树一起跑时用它。作者检查改动文件时不带这个选项，才能看到每条提示的位置。未过滤的文本和 JSON 用 `sentence-length-caution` 表示 30 至 40 字，用 `sentence-length` 表示超过 40 字。

`--changed 文件` 把报告限定在本次改动碰过的段落。文件每行写 `路径:起-止` 或 `路径:行`，`#` 开头是注释。没有写进去的文件一条都不报。两侧相对路径均以本次工作目录为基准。能取得真实路径时，再解开符号链接。范围文件写 `docs/x.md` 或命令行传 `./docs/x.md`，均匹配。传绝对路径也匹配。经符号链接到达的同一目录亦然。推导行号要读 Git，属于调用方职责。本工具接收行号，不自行计算。

调用方对只删不增的 hunk 写删除落点旁边那一行。那种 hunk 在新侧不留任何行，写不出条目就等于不写。删除会合并前后两段行文。不写该行，就会把句长提示错归给别人。

范围点名了本次未扫描的文件时只计数，不报错。计的是调用方写下的条目，不是它点名的文件。一个文件在 diff 里常有几个 hunk，所以两个数不一样。按条目计，这个数才对得上调用方自己的范围文件。diff 推导的范围也含非 Markdown 文件。`--exclude` 还会排除一些。拒绝运行会让一次普通改动跑不起来，沉默又会藏掉写错的路径。

归属按段落而不按行。行文先合并折行，再度量整段。跨第 12 到 14 行的句子可能记在段首第 10 行。只拿发现行号比对改动行，会漏掉新写句子。改动向段落加入行时，按段落判定。增加或替换行的 hunk 都适用。代价是同一段里既有的发现也一并算进来，那是安全的方向。

每次运行都说明有多少发现落在改动之外。只报改动内的发现而不说这件事，读起来就像文件是干净的。`--changed` 不与 `--fix` 同用。修复循环按整个文件推理。一个空格可能让更早的空格安全。

定界跨度内部的文种变化不报。空格只能写到代码或地址里，并非行文。贴着跨度两侧的边界照常报。行内图片按分隔处理，它渲染出一个图形，两侧的文种已经分开。

`--fix` 只补中西文之间缺失的空格，写回原文件。一次调用补到不能再补，剩下的都带不可修标记。它不改标题、表格单元格、引用与代码。简写与折叠的引用式链接，标签就是它的标识符，里面不补。补进去它就匹配不上定义。没有定义时它只是文字，照常补。它也不改句长，在哪里断句是作者的判断。字符实体与转义照常补，位置落在整个构造之后。位置已知、但写进去会改坏构造的地方不补，报告尾部给出 `position unrecoverable`。引用标签那一类给引用自己的标识符；裸地址那一类把地址定界成 `<…>`。还有两类位置本就无从得知。极少数实体解码出多个字符，全角标点后的地址由树变换单独生成。这两类整段不修，空格由作者自己写上。不要用 `<…>` 括后一类，那会把后面的正文吞进链接目标。

句子超过 40 字时，检查可用标点边界。若两半均不超过 40 字，报告 `split 头+尾`。这只是编辑建议，没有这样的边界就不给建议。

补空格后，紧贴汉字的裸地址可能变成链接。分隔后它才满足自动链接条件。这是合规写法本来的样子。但地址右侧还贴着中文时不补。新链接一直延伸到下一个空格，会把正文吞进目标。那一处报为不可修，由作者安排空格或写成 `<…>`。

裸地址一直延伸到下一个空格，所以紧跟其后的中文在链接里面。它按地址在文种变化处结束来读。后面的中文照常计入句长，接缝照常报。但不修改：那个位置若落在真含中文的地址里，会劈开链接。地址自己带中文时也按这条读：那一段计入句长，接缝照报。写成 `<…>` 才归入地址，那样整段不报。

以下说明检查器目前如何近似判定语言。作者不必按字词比例改写正文。检查通过也不能证明文档的主要语言合适。句长同时考虑句子和所在段落。不能只看出现过哪种字符。汉字数与拉丁词数哪边多，就算哪边。所以英文行文里引用一句中文，不套用整句中文阈值。中文句子列举一串拉丁名，仍然套用。空格不按这条判，两种文字相遇就要空格。括号、引号和行内构造仍可能造成混排漏报。作者必须人工复核这类段落。

判为拉丁行文的那一段不是不查，是**只量它带的中文**。这条规定写在[写作规范](writing.md)的中文小节里，本页只说它怎么量。若把拉丁字符算进中文句长，提示数字会描述一句并不存在的中文。只量中文，两种情形说的都是真话。引用的是个短语，谁都不报。引用的是一段够长的中文，就按它自己的长度报。作者判断是否需要断句，不必把引用删掉。

量的是最长的一段连续中文，不是加总。四段八个字的引语就是四个短语，加起来不是谁写下的一段话。连续中文算到分隔小句的标点为止。带逗号的引语仍是一段。`。！？` 在上一步已经分过句。空白及行内代码不计长度，也不打断中文段落。比较各段长度时同样忽略空白。

中间夹一个术语不算断开。`中间用到 Node 这个工具的名字` 是一段，因为标识符站在中文里面。术语内部的连字符、点、下划线与斜线算在一起。`check-prose.mjs` 与 `CI/CD` 都是单个名字。空格不在其内，所以 `Markdown lint` 仍算两个词。夹着两个以上拉丁词才算断开，那时量的是较长的半边。不这样接续，同一句中文量不量就取决于前面的英文怎么收尾。句号那边有分句边界，逗号那边没有。

拉丁词只数字母，数字不算。数字两种文字读法相同，不能作为任何一边的依据。中文句子里列一串版本号，仍按中文度量。

判定语言时汉字按总数算，不按最长一段算。这两种算法实测过。按最长一段算，`Node、Bun、Markdown lint、ShellCheck、…` 这类逐个点名工具的中文句子会判成拉丁行文。本仓库当场少两条发现。英文段落并排引用四个中文短语时，可能误判为中文。按整段报告的长度可能难以消除。**规则对中文行文沉默比多报一次重**，所以取总数。

英文句号后接空格与汉字，也是一处分句边界。中文的断句符号不含英文句号。不在这里分开，写在英文后面的那句中文就与它合并度量。同一句话会按排在前还是排在后，得到两种结果。

句号之前那一段按同一套算法判定语言。不能只看是否出现汉字。判为中文时句号结束的是句中缩写，不是这句话，例如 `用到缩写 e.g. 后面`。**按「出现过汉字」判会丢发现。** 英文段落引用四个汉字后，接一句 53 字中文。若未断开，两者无法区分。整段于是判成拉丁行文。最长一段中文只剩 26 字，一条都不报。同一句话跟在不引用中文的英文后面，报的是 53 字。一句中文量不量，不能取决于它前面的英文引了什么。

它报告中文句长，并判定中西文空格。句长报告由作者按意思判断，不影响退出码。其他写作约定也由作者判断。通过检查不等于整段合规。

`grades` 子命令列举分级词候选：`node "${AGENTS_DELIVERY_ROOT}/tools/check-prose.mjs" grades PATH...`。它只列举，不判定。候选是站在封闭集之外的分级词：`须`（不在 `必须` 里）、`需要`、`都要`、`不能`、`可以`、`应该`。裸 `需` 与裸 `要` 不在表内，它们多为叙述用法，会把清单淹掉。判定一句是规定还是叙述由作者完成，所以每条候选都带整句。它读与句长同一份行文。标题、表格单元、引用及代码中的词不算候选。行内代码也不算。它不接受 `--fix`，改措辞由作者写。它也不接受 `--errors-only`，因为候选没有严重度可供筛选。

退出码 0 表示无空格错误，1 表示有空格错误，2 表示用法错误。30 字及以上的句长发现都是警示。超过 40 字仍给出断句建议，退出码不变。`grades` 无论有无候选都退出 0。它是清单，不是判决，不要把它接进门禁。

## id-check

本节是 `id-check` 的调用说明。主体定义在仓库的 `scripts/check-ids.mjs` 头部，不在本页。

运行 `node "${AGENTS_DELIVERY_ROOT}/tools/check-ids.mjs" PATH...`。目录遍历、`--exclude`、`--format` 与 `--version` 同上。

它不接受 `--changed`，这个省略是有意的。顺序错误报在下降的那一行，不报在它所下降的那一行。所以在 `X-04` 与 `X-06` 之间插入 `X-09`，错误报在作者从未碰过的 `X-06` 行。按改动行限定范围正好藏掉这次插入造成的缺陷。散文检查器按改动范围触及的段落判定。编号顺序涉及一对行，错误可能落在未改的后一个编号上。

它检查表格首列的标识符。同一前缀的编号必须按出现顺序递增，标识符不得重复。两条都按文件判定：各文档给自己的表格编号，跨文件重名不报。跳号允许，回退不允许。行从语法树读取，所以代码块里形似表格的一行不算。

默认形状是 `^([A-Za-z][A-Za-z0-9]*)-(\d+)$`。用 `--pattern` 换成项目自己的形状，正则必须有前缀组与数字组。退出码 0 表示无编号错误，1 表示有编号错误，2 表示用法错误。

## ref-check

本节是 `ref-check` 的调用说明。主体定义在仓库的 `scripts/check-refs.ts` 头部，不在本页。

它不随交付发布，只在 agents 仓库里运行：`node scripts/check-refs.ts`。它把发布树摆进临时目录，再用已固定的 lychee 跑一遍。仓库形态也由同一 lychee 检查。文档组使用相同的 `lychee.toml` 参数。两种形态因此使用一致的链接规则。两者问的不是同一个问题。

同一份文件在两种形态下深度可以不同。仓库中的 `docs/x.md` 发布到公共根后，路径会变化。其中的 `../policy/y.md` 在仓库可解析。它在发布根之外。这一类断链只有按发布形态验才看得见。

发布布局取自 `scripts/delivery.ts` 的 `publicMembers`，不在检查器里另列一份。另列一份可能与安装器构建的树漂移。检查结果就不再对应实际安装的树。摆树与安装器使用同一份当前源码清单，包括仍存在的 Git 跟踪文件和未忽略的未跟踪文件。成员来源不存在时检查器会失败。若静默少摆一份，发现会变少而不报错。

解析交给 lychee，不在这里自己做。跑出发布根的引用另算一遍。lychee 将相对链接解析到真实文件系统。只要目标存在，它就判为通过。对消费者来说，发布根之外的目标无法交付。所以那一类由链接清单判，不由文件系统判。

已知缺口写在检查器里，每条带承担它的切片。清单外的发现一律阻塞。**清单里不再出现的条目同样阻塞。** 允许项活得比它允许的东西久，读起来像覆盖而实际不承担。

退出码 0 无阻塞发现，1 有阻塞发现或有陈旧允许项，2 用法错误。
