# Antigravity behavior

- This native global rules entry serves Antigravity CLI and App. The entry's asset root is the adjacent `config/` directory: references to the product delivery root in shared instructions mean that asset root, not the directory containing this entry. Shared policy, skill, and tool links resolve through `config/`, both clients discover personal skills under `config/skills/`, and [Antigravity runtime and CLI policy](../policy/antigravity.md) holds detailed runtime and CLI rules.
- Use the running CLI or App's actual tools, instruction discovery, and project context, verifying each executor's repository and candidate under the [execution context contract](../policy/tool-contracts.md#执行上下文). Do not assume the App, CLI, and IDE share a current directory, `<appDataDir>`, tool inventory, session state, or accepted permissions. Honor native file-editing and permission mechanisms without assuming Codex chat tools, Codex model defaults, or a substitute for native client permissions. Subagents, `swarm`, `run_workflow`, background tasks, and `schedule` wake the session reactively; continue independent work or end the turn instead of polling in loops or running shell `sleep` timers.
- Antigravity has no implicit `memory` tool; persistence runs through explicit Rule and Skill files, including `/learn` outputs. Do not hand-edit generated `~/.gemini/AGENTS.md` (or `~/.gemini/GEMINI.md`) or write unapproved workspace `.agents/` customizations as implicit memory. Maintain durable rules at their authoritative source, and keep `~/.gemini/AGENTS.md` compact well below the `24,000`-byte per-file rule cap and shared `20,000`-token inline rules budget by placing detailed guidance in `config/policy/`.
- In inspection, review, or read-only analysis tasks, a "do not modify files" constraint protects the inspected repository checkout, external materials, and managed configuration. Unless the Human explicitly forbids session `brain/` writes, the current session's `<appDataDir>/brain/<conversation-id>/scratch/` (and explicitly requested session Artifacts) may hold session-internal drafts and handoff files without touching the target checkout; apply [temporary-directory](../policy/execution.md#task-temporary-directories) and [exercise cleanup](../policy/execution.md#test-and-exercise-cleanup) at closeout.
- Subagent `send_message` payloads have a hard `20,480` UTF-8 byte ceiling and truncate above that limit, and `write_file` in a subagent can write only to that subagent's own `<appDataDir>/brain/<self-conversation-id>/scratch/`, never the parent session's `brain/` directory. When a subagent or multi-stage worker has write tools and produces a report or analysis approaching or exceeding the limit (such as over `16 KB` UTF-8), write the complete unedited output to the subagent's own `brain/<self-conversation-id>/scratch/` and return that file's absolute path with a concise summary via `send_message` for the parent to inspect via `read_file`. Never instruct a subagent to write into the parent's `brain/`, loop over shell or Python byte-count checks, or destructively trim substance to fit one message; when running in a read-only sandbox without write tools or refused by the host, preserve the refusal and return once in a compact structure or ordered parts without unbounded recalculation.
