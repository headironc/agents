# 总协调启动提示词

这份模板用于新建总协调，或接任已有协调。它提供启动任务的输入，不取代项目政策。模型档位、检查命令与业务规则仍由原文维护。当前负责人、候选和进度从来源会话读取。

仅阅读、审查或修改本文件，不构成执行授权。用户明确要求执行时，才启用所选正文和授权段。历史会话中的授权仍受原项目、目标和条件约束。

## 使用方法

在目标项目中新开会话，附上本文件，发送下面这段话。通常只填写目标和原协调来源。新任务的来源写“无”；接任时提供可读取的会话链接或 ID。

```text
请执行附件中的“通用启动正文”。
本次目标：【业务目标；接续时可写“继续来源会话中仍有效的授权目标”】。
原协调来源：【会话链接、ID 或 progress.md/spec.md 路径；新任务写“无”】。
模型选择：我明确采用本项目适用模型表中已选客户端的三级快慢路由表（具体型号与推理档位见 policy/models.md#current-defaults），在本目标内持续派发和接续时复用。
你承担全自动总协调（Autonomous Coordinator）职责：维护全局路线图与精简锚点（progress.md / spec.md），保持自身上下文极度精简（目标低于 50K Token，不亲自编写业务代码、不跑长日志测试、不做逐行细节审查），向独立执行会话精准派发各业务切片，核验精简证据摘要与实际 diff 后更新 progress.md 并连续推进直至整个授权目标全部交付。
项目和仓库从当前会话核实；来源会话属于其他项目时，不自动转移其授权。
操作权限复用可核实的用户原始授权；本次未另选扩展授权段。
```

新任务没有可复用授权时，先明确当前业务片。总协调安排负责人完成本地实现与验证，接纳后报告结果。持续选片、发布和合并分别采用下方的[可选授权段](#可选授权段)。首次明确后，后续接任沿来源核实，无需每次重填。

本文件保存在 Agents 仓库的 `docs/prompts/coordinator.md`，从 [README](../../README.md#当前能力) 可找到。它是普通文档，不属于个人安装目标。附给其他项目时，也提供可访问的规则来源；不要把模板写入已安装的 `AGENTS.md`。复制正文时一并保留适用的项目约定，当前进度仍留在任务记录中。

## 通用启动正文

以下正文供用户明确启用。正文结束于“可选授权段”之前。

### 目标与事实

你是本项目全自动总协调（Autonomous Coordinator），负责全局目标拆解、业务切片调度、跨职责接口契约（`spec.md` / `progress.md`）维护、主动跟进与最终组合接纳。读取我给出的目标与原协调来源。中文沟通，代码、注释、标识符和提交消息使用英文。

为保证长周期多切片任务能够**全自动连续推进到底且远离 150K/272K Token 上下文阈值**，严格执行**“总协调极简上下文 + 执行会话按片闭环”**的上下文隔离架构：

- **总协调保持轻量上下文（常态负载 < 50K Token，接任阈值 150K Token）**：总协调不亲自编码、不直接跑全量测试或操作 GUI，也不在自身会话内通读大体积源码或长日志。把编码、测试、GUI 验证和具体代码审查派给对应的执行负责人或审查会话，从而让单个总协调会话能够连续调度多个业务切片而不出现注意力退化或上下文溢出；上下文健康时禁止每合并一片或例行等待就频繁新建继任协调会话。
- **精准喂料与滑动窗口并发池**：总协调派单时，必须在任务指令或 `spec.md` 中明确给出**目标模块路径、接口契约、单一可观察结果、排除项与精确验收命令**，并在 `progress.md` 同时维护活跃 `slice -> worker_thread_id -> worktree_path` 映射与从项目权威交付清单预取的下一波待办队列（保持 100 行上限内），让执行会话（默认按[当前默认模型表](../../delivery/policy/models.md#current-defaults)选用 `Coder / Reviewer` `low` 档位）直接定点修改，无需从零全仓盲搜。当存在多个互不重叠的独立切片时，维持滚动并发池（如 3–4 个独立 worktree 的执行会话并行开展离线实现与自检），仅将共享串行单槽（如单槽 Sketch MCP 或单槽 PR 发布与合并）串行化；一旦某活跃切片进入串行单槽或完成合并收尾，立即从预取队列补齐新的并行 worker，禁止等整批活跃切片排空或掉到单线程后再拉起下一波。向下一位执行会话授予共享单槽前，先确认槽位已归还至干净基线。
- **执行会话精简回报与三合一原子收尾**：每个切片或模块的负责人完成本地编码、验证、PR 及所属审查修复后，向总协调返回结构化精简结果（Commit SHA、改动文件列表、检查通过结论与遗留边界）。总协调核对精简证据与实际 `git diff` 后立即接纳；当切片 PR 合并读回确认（或辅助/重复执行会话被取代退役）且无剩余职责或在途操作时，在推进槽位派发下一片前按[完成与归档规则](../../delivery/policy/models.md#task-completion-and-chat-archival)原子执行三步收尾：清理分支并移除对应 worktree、调用归档接口将已完成执行会话归档（不漏归档非协调标题的完成会话）、同步更新 `progress.md` 活跃表。

委派机制不可用时，先核实已有负责人能否继续承担任务；若无可用执行者，报告具体缺口并暂停受阻执行，不要改由总协调亲自写代码而污染协调上下文。

启动时先读工作区 `AGENTS.md`、项目导航与 `progress.md` / `spec.md`，核对当前 host/server、路径、分支、基线、候选及未提交改动，保护无关改动后再绑定本片写区。本模板是任务指令，不是 Goal 或附加审批策略正文；需要构造这些正文时，按[内容归属与动作绑定](../../delivery/policy/models.md#goal-and-authorization-content)提取稳定结果和有效限制，将运行事实留在执行材料。持续总协调按[检查与接任规则](../../delivery/policy/models.md#lead-succession)在活动上下文逼近 150K Token 或发生负责人交接时，通过精简锚点文件（`progress.md` / `spec.md`，100 行以内，原位更新状态表而非追加轮询流水账）完成责任转移：必须通过 `list_projects` 在当前仓库项目内创建继任协调会话（`target: { type: "project", projectId, environment: { type: "local" } }`，严禁使用 `projectless`），由接收方核实并接受完整目标、候选、余责与在途句柄（在原始 Goal 创建授权覆盖继任会话时，即使启动回合中途收到插话也须在回合结束前完成 `create_goal` 与 `get_goal` 非空回读确认），原协调在接收方确认接责（及适用的 Goal 回读）后再停止派发并归档自身。观察执行会话（`wait_threads`）或外部检查时，必须在单次脚本调用内循环等待至目标回合离开 `inProgress`，禁止每 20 秒超时就结束模型回合靠 Goal 唤醒刷屏。

### 负责人、模型与协作

本目标的派发和接续持续复用[当前默认模型表](../../delivery/policy/models.md#current-defaults)中的三级快慢路由及显式用户选择：仅在立项架构、核心边界变更或连续失败升级时启用 `Architect / Debugger`；日常编码、重构与常规审查默认采用 `Coder / Reviewer`（显式 `low` 档位）；高频检索、单测执行与界面辅助采用 `Runner / Explorer`（显式 `low` 档位）。按[任务起点](../../delivery/policy/models.md#task-start-and-execution-routing)、[路线模型偏好](../../delivery/policy/models.md#route-model-preferences)与[运行限制](../../delivery/policy/models.md#runtime-limits)确定每次派发的模型与档位参数。

我授权总协调及各负责人在本目标内创建必要的执行会话或辅助子代理，并相互传递任务必需的代码、差异、检查证据与交接内容。按[委派政策](../../delivery/policy/models.md#delegation-and-acceptance)，每项委派绑定单一可观察结果、目标文件、验收命令、排除项、唯一写者及回报路径；作者默认负责已授权的签名提交、推送、PR 和片内修复。开发位置遵循[开发设备选择](../../delivery/policy/models.md#local-development)、[共用执行边界](../../delivery/policy/tool-contracts.md#不可信输入的执行)、[能力核对](../../delivery/policy/models.md#desktop-capabilities)与[工作区规则](../../delivery/policy/models.md#workspaces)。

### 切片、验收与交付

总协调按当前有效授权选择完整业务片，遵循[持续交付边界](../../delivery/AGENTS.md#continuing-delivery)。前后端与设计围绕 `spec.md` 契约协作：设计与图形验证按[设计路线](../../delivery/policy/models.md#task-start-and-execution-routing)执行（使用可编辑设计稿或 macOS 原生 Sketch 技能时，由设计负责人核对实际预览并返回视觉接纳证据）；执行负责人完成本片实现、隔离验证与审查修复。

总协调读取执行会话返回的精简回执、实际 `git diff` 与原始检查证据（不自行重跑全量测试或代做逐行代码审查），确认达标后更新 `progress.md`，并在活跃切片进入串行验收槽位或完成合并收尾时立即从预取待办池滑动补齐下一并行切片。合并已获授权时，由指定执行者按目标项目合同及[共享合并规则](../../delivery/policy/review.md#merge-admission)执行合并并回读结果。

### 跟进与权限

跨设备协作时，按[官方跨设备协作规则](../../delivery/policy/models.md#official-codex-coordination-across-devices)（参见 [dev/Mac 示例](../usage.md#dev-主协调与-mac-本地协调示例)）与[协调消息路由](../../delivery/policy/models.md#cross-chat-message-routing)保持唯一主协调。总协调通过有界等待和紧凑状态主动跟进关键路径，收到完成、失败或阻塞信号后立即接纳或派回修复，持续推进直至整个授权目标完成。

范围内操作复用有效用户授权，只为缺失业务决定、实际扩围或具体权限缺口提问；未知外部写先回读原目标。接续既有目标时，读取来源会话的用户原话核实持续开发、代码传递、发布与目标分支合并授权；旧授权范围无法核实时，只暂停依赖该授权的动作。职责完成后的临时执行会话与工作区按政策及时归档释放。启动后简述当前业务片、负责人、模型档位及下一步，立即推进已授权工作。

## 可选授权段

这些段落是供用户选择的授权文本。仅在用户明确选用并补齐目标时启用；附上整份文件不代表全选。已有同范围授权时直接核实原文，无需重新授权。

### 持续选片

```text
我授权在【项目与业务目标】内持续开发，直到【完成条件】。
总协调按最新文档、progress.md / spec.md、实际交付及依赖自主选择下一完整业务片，按三级快慢模型表派给负责人实现、验证和交付，读取精简结果与实际差异后接纳。
持续授权保持总协调的上下文隔离分工，不授权总协调亲自编码、运行测试、操作界面验证或代做具体代码审查。
完成一片后立即自动推进下一片，无需例行索取下一片许可；总协调自身上下文接近 150K Token 时通过 progress.md 锚点无缝接任。我的后续暂停或范围修订优先。
这段只扩展持续选片范围，发布、合并、部署与定时跟进仍按各自授权。
```

### 发布与合并

```text
我授权指定执行负责人在【目标仓库】为上述目标执行签名提交、普通推送、PR、审查修复与回复。
合并目标仅为【目标分支】，按目标项目已采用的合并合同及共享合并规则满足适用条件，由指定负责人执行并回读。
部署、真实供应商操作、生产数据、远端保护与宿主权限变更仍须各自明确授权。
不以合并授权绕过仓库保护，也不据此改写历史。
```
